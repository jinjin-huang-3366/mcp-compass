# MCP Compass v0.1.0

MCP Compass turns a natural-language agent capability requirement into ranked MCP server recommendations with
evidence about fit and gaps. Try the [public demo](https://mcp-compass-iota.vercel.app/) or start with the
[README](https://github.com/jinjin-huang-3366/mcp-compass/blob/v0.1.0/README.md).

This is the first public release. The `v0.1.0` version reflects an early public developer release with material
limitations; it is intentionally independent of the repository's internal V0.7 delivery-plan numbering.

## Highlights

- Search locally synchronized public MCP Registry metadata using required capabilities, forbidden capabilities, and
  hard constraints; the interactive search path does not proxy each query to the public Registry.
- Inspect ranked matches, parsed intent, matched and missing capabilities, score explanations, and calibrated
  no-strong-match abstention.
- Review an OpenAPI-derived MCP tool contract before exporting a GitHub-ready TypeScript project when reuse is
  inadequate.
- Use the web interface, CLI search and generation commands, or IDE launch integrations.
- Submit generated projects to a separate queued validation control plane with bounded container and protocol checks.

The fixed 53-judgement demo-quality gate recorded 96.2% Recall@100, 0.8620 NDCG@10, 24/24 top-three acceptance, zero
forbidden-result violations in the top three, and 8/8 correct abstentions. These are dated evaluation results, not a
claim about every MCP server or every requirement. See the
[evaluation report](https://github.com/jinjin-huang-3366/mcp-compass/blob/v0.1.0/docs/reports/DEMO_QUALITY_GATE_V1.md).

## Known limitations

- Registry data is a synchronized snapshot, not complete live ecosystem coverage.
- The demo uses a Vercel alias rather than a custom domain.
- Hosted validation requires a separately operated isolated worker. A queued validation job or report is bounded
  evidence, not a security certification.
- Generation targets the repository-owned TypeScript runtime pack.
- Optional LLM analysis, embeddings, and GitHub enrichment require separately configured providers.
